# Odovi 0.4.0 release notes

Release version: `0.4.0`

Install the immutable Compose asset attached to the stable GitHub Release.
Its web and worker digests identify the accepted builds. Candidate tags and
source checkouts do not replace the published release asset.

## Highlights

- **Paper & Ink interface:** a quieter application palette and typography,
  clearer navigation and overview, and direct drive classification with guarded
  undo. Existing routes, provider choices and archive data are retained.
- **Driving profiles:** choose private, business or balanced use per vehicle.
  Automatic defaults apply to completed drives that started after the profile
  was chosen. User rules and manual decisions retain precedence. Applying a
  profile to unclassified history is a separate action with guarded undo; existing
  classifications and notes are preserved.
- **Journey and day recaps:** a continuous camera follows the recorded route
  by distance. Short drives receive shorter sections while every item stays
  reachable. Charging stops have their own card surface, charging icon and
  counter. Missing GPS is not presented as a recorded road. Keyboard navigation,
  dark mode and reduced-motion controls remain available.
- **Charging prices:** clearing a manual price immediately uses an available
  place tariff. Without usable tariff or energy data, the manual marker is
  cleared. The form shows the saved result.
- **English presentation:** overview, day and drive views use the selected
  language for numeric values and open-session time labels.

See [driving profiles](../driving-profile.md) and
[journey recaps](../journey-recap.md) for behavior and limits.

## Upgrade from 0.3.0

No database migration or runtime-configuration change is introduced relative
to 0.3.0. Preserve the existing Compose project, database volume, credentials,
network overrides and provider decisions. Back up the archive and verify a
restore before changing a real installation.

A driving profile does not automatically reclassify historical records.
Earlier classifications and manually entered charging costs remain intact.
An already empty manual-price override is repaired when that charge is saved
again; this release does not bulk-rewrite charging records.

Follow the [upgrade and recovery procedure](../upgrade-odovi.md) for the
versioned Compose asset and a current database checkpoint.

Installations still named Tripatlas should follow the historical
[rename procedure](../rename-to-odovi.md) first.

## Supported runtime

- Application: Node.js 22, included in the web and worker images.
- Database: PostgreSQL 17.
- Orchestration: Docker Engine with Docker Compose v2.
- TeslaMate: 4.0.1 through 4.2.0, read-only. The boundary versions have schema
  fixtures and synchronization-query coverage.
- Images: `linux/amd64` and `linux/arm64` from one accepted source revision.

## Tested platforms

The exact published candidate passed the complete GitHub CI and application
acceptance gates for `linux/amd64`, plus image identity and license checks for
both supported architectures. Native Raspberry Pi 5 acceptance passed 26 browser
tests with one documented duplicate locale check skipped and no failed or flaky
tests. All 107 provider requests in the controlled contract test stayed within
the fixture providers; no unexpected provider request occurred.

A separate native rehearsal upgraded published 0.3.0 to these images, restored
the current backup and rolled back to the original images and checkpoint.
All four phases passed, including preserved sessions, fresh logins, byte-identical
CSV/GPX exports, 23-table checkpoint comparisons and both backup checksums.

The [acceptance summary](../../release/0.4.0/acceptance-summary.json) records the
source, exact image digests and workflow links. The GitHub Release also includes
this summary and `release-candidate.json`. Stable promotion keeps the accepted
candidate digests unchanged and does not rebuild the images.

## Known limitations

- One vehicle per installation remains the supported focus, although profiles
  are stored per vehicle.
- An existing supported TeslaMate database is required and is not bundled.
- TeslaMate 4.0.2 through 4.1.x are bounded by the tested 4.0.1 and 4.2.0
  endpoints; not every intermediate patch has its own fixture.
- Route and map coverage depend on recorded GPS and explicitly enabled
  providers. Missing data is not reconstructed as recorded movement.
- A full viewport resize can change the currently visible recap chapter;
  touch address-bar-only resize does not rebuild its scroll timeline.
- The roadtrip planner remains experimental. Provider activation and actual
  route calculation are explicit steps.
