# Odovi 0.3.0 release notes

Release version: `0.3.0`

Install the immutable Compose asset attached to the stable GitHub Release.
Its web and worker digests identify the accepted builds. Candidate tags and
source checkouts do not replace the published release asset.

## Highlights

- **DC charging comparison:** compare the latest 5 or 10 completed fast charges
  by state of charge, observed average and peak power, 10–80% time, and location.
  Incomplete timings remain unavailable; slower-session hints explain their
  comparison basis and do not diagnose battery or charger problems.
- **Yearly destination visits:** filter completed-drive arrivals by year and
  classification, view the most-visited destinations, and use the heatmap with
  the existing reviewed map provider. This measures destinations, not road
  traffic or route density.
- **Odovi Wrapped:** review annual distance, driving time and energy,
  classification totals, twelve months, the longest drive, favorite destination,
  and farthest destination from a saved Home. Charging covers the entire selected
  year, with separate totals for each recorded currency.
- **Browser printing:** print Wrapped or save it as a PDF with readable light
  styling, preserved year and filter context, and the available destination map
  and list.
- **Navigation:** Calendar is in the mobile bar, Search is available in the
  header, and the analysis views retain the appropriate active destination.

The new views are available in English and German. See the
[feature definitions](../../README.md#compare-dc-charging-sessions) for timing,
data coverage, destination grouping, and comparison rules.

Thanks to [@Pischleuder1](https://github.com/Pischleuder1) for the proposal behind
the charging comparison and yearly destination insights in
[#47](https://github.com/jsc2304/odovi/issues/47).

## Upgrade from 0.2.0

This version introduces no database migration or runtime-configuration change
relative to 0.2.0. Preserve the existing Compose project, database volume,
credentials, network overrides, and provider decisions. Follow the
[0.2.0 → 0.3.0 upgrade procedure](../upgrade-odovi.md), including a verified
backup and a restore rehearsal before changing a real installation.

The published 0.2.0 → 0.3.0 upgrade, backup restoration and rollback passed in
an isolated ARM64 stack, preserving records, sessions and CSV/GPX exports.

Installations still named Tripatlas must first follow the historical
[v0.1.1 → v0.2.0 rename procedure](../rename-to-odovi.md). The new analysis views
read Odovi's existing archive and retain the TeslaMate read-only boundary.

## Supported runtime

- Application runtime: Node.js 22, included in the web and worker images.
- Database: PostgreSQL 17.
- Orchestration: Docker Engine with Docker Compose v2.
- TeslaMate: 4.0.1 through 4.2.0; the endpoint versions have schema fixtures and
  synchronization-query coverage. See the [compatibility matrix](../teslamate-compatibility.md).
- Images: `linux/amd64` and `linux/arm64` from one accepted source revision.

## Known limitations

- A complete 10–80% charging window needs usable continuous SoC measurements;
  incomplete or inconsistent data is not extrapolated into a result.
- Charging comparisons describe the selected recent history. Outside temperature
  is not battery temperature and does not establish why a charge was slower.
- Unsaved destinations use an approximate 0.001° coordinate grid. Nearby points
  on opposite grid boundaries can appear as separate destinations.
- Farthest destination is straight-line distance from a saved Home, not driving
  distance. No Home is inferred from frequency or a place name.
- Charging totals cannot follow a drive-classification filter, and currencies
  are not converted or combined.
- Maps require an explicitly activated provider. Counts and reports remain
  available with map tiles disabled. Printed maps reflect the tiles available
  in the browser when printing.
- One vehicle per installation remains the supported focus. An existing
  supported TeslaMate database is required and is not bundled.
- TeslaMate 4.0.2 through 4.1.x are bounded by the tested 4.0.1 and 4.2.0
  endpoints; not every intermediate patch has its own fixture.
