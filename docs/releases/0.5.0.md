# Odovi 0.5.0

Release version: `0.5.0`

Compared with stable 0.4.0, this release adds:

- **Battery range history:** monthly post-charge rated-range medians and their
  change from the first month with usable range observations, with measurement coverage.
- **Charging economics:** energy losses, weighted charging efficiency, and
  matched costs by currency, charger type and location.
- **Since the last charge:** dashboard driving totals with explicit estimates,
  missing data and charging boundaries.
- **Local invoice archive:** optional PDF/ZIP originals with hashes, reviewed
  charging matches, explicit reversible cost enrichment and monthly evidence
  exports. Imports are disabled by default and run without an external service.
- **Persistent classification Undo:** the latest quick classification can be
  undone for 30 minutes in its original authenticated session, including after
  navigation/reload. Conflicting later changes reject the undo safely.
- **Archive and navigation improvements:** clearer quick-classification actions,
  explicit Save/Discard for detailed annotations, unsaved-change navigation
  guards, and keyboard-accessible archive navigation.

See [Battery and charging analytics](../energy-analytics.md) for the calculations
and their limits. See also the [invoice archive](../invoice-archive.md) and
[classification and Undo](../classification-undo.md) contracts. English and
German are supported throughout.

## Security and release integrity

The release updates Next.js to 16.4.1, Zod to 4.6.6 and affected transitive
dependencies. Production dependencies must pass the current security audit.
Stable promotion authenticates the selected candidate workflow/run attempt and
keeps verification code pinned to the trusted promotion revision.

## Supported runtime

- Application: Node.js 22 in container images.
- Database: PostgreSQL 17.
- Orchestration: Docker Engine with Docker Compose v2.
- TeslaMate compatibility boundary: 4.0.1 through 4.2.0.
- Image platforms: `linux/amd64` and `linux/arm64`.

## Upgrade and recovery

Back up the Odovi database with the existing
[upgrade procedure](../upgrade-odovi.md) before installing this release.
Published stable 0.4.0 ends at migration `0008`. The upgrade applies `0009`
(classification Undo receipts and revision trigger), `0010` (invoice storage),
and `0011_battery_rated_range` (nullable charging range). Some source-based
0.4.0 installations already contain `0009`/`0010`; the journal applies only
missing entries.

Migration `0011` resets only the TeslaMate charging watermark once. The next
successful charging sync enriches historical range, which can take longer for
a large archive. No source TeslaMate writes or new provider activation are
required.

Existing notes, prices, classifications, locked places and provider decisions
are preserved. Keep the original environment, overrides and database identity.
Restoring the pre-upgrade backup remains the rollback path; use the matching
previous application version after restoring it.

## Known limitations

- Battery range is a BMS estimate relative to recorded history, not a factory
  health score, diagnosis or verified capacity measurement.
- Imports without independent rated-range measurements have no battery trend.
- Missing energy pairs and prices reduce the coverage of efficiency and cost
  calculations; unknown currencies are never inferred.
- TeslaMate 4.0.2 through 4.1.x are bounded by the tested 4.0.1 and 4.2.0
  endpoints; each intermediate version does not have a dedicated fixture.
- One vehicle per installation remains the supported focus. A supported
  TeslaMate installation is required.
